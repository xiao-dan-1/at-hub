# AT 本地解析器 V2 设计

## 1. 目标

V2 将现有“可用的 JWT 数据查看页”升级为个人专业工具：用户粘贴一个 ChatGPT JWT 形式 AT 后，先得到可快速判断的安全与账号摘要，再按需查看权限、字段详情和脱敏 JSON。

完成标准包含：

1. 默认界面像安全控制台与账号仪表盘，而不是原始 JSON 展示页。
2. 真实 OpenAI 命名空间被归并，常见 claim 有中文名称、解释和风险语义。
3. 保持纯本地、零联网、零持久化、不验签、默认脱敏和单 AT 范围。
4. 开发源码工程化，发布产物仍是一个可通过 `file://` 双击运行的 HTML。
5. 桌面、手机、浅色、深色和纯键盘均能完成完整流程。

## 2. 用户与产品定位

用户是项目所有者本人，熟悉基本技术概念，重视效率、准确性和隐私，不需要营销内容或新手教学。

产品定位是“ChatGPT AT 本地检查器”，不是通用 JWT 编辑器，也不是账号登录、token 刷新、额度查询或代理工具。界面可以显示 JWT 声明，但不能把声明描述为服务器当前事实。例如套餐应标记为“JWT 声明的套餐”，并说明它可能陈旧。

## 3. 设计原则

1. **状态优先**：先回答“时间窗口怎样、是否验签、有哪些高风险权限”。
2. **语义优先**：先显示人能理解的中文信息，原始 key 作为次要证据。
3. **渐进展开**：概览保持紧凑，完整字段只在高级检查器出现。
4. **隐私默认**：身份、账号、会话和邮箱等值默认遮罩，显示是短暂且可撤销的。
5. **准确表达不确定性**：解码、时间判断、JWT 声明和服务器真实状态明确分开。
6. **工具而非展览**：不使用大幅 hero、装饰性渐变、花哨动画、过度圆角和满屏卡片。

## 4. 信息架构

### 4.1 空白状态

页面顶部是 56px 应用栏，包含产品名 `AT Inspector`、本地运行状态和主题跟随说明。主体只放一个输入工作区：标题、AT 文本框、解析按钮、清空按钮和简短安全提示。

首屏不使用巨大标题。桌面内容宽度控制在 1120–1200px，手机使用 10–16px 页面边距。

### 4.2 结果状态

解析成功后，输入工作区折叠为紧凑工具栏，包含“重新解析”“清空”“复制脱敏 JSON”。页面主体分为三个标签：

- **概览**：安全状态、时间、账号、套餐、认证和权限摘要。
- **权限**：逐项解释 scope，按模型调用、读取、写入、身份和离线访问分组。
- **高级检查器**：字段搜索、分类筛选、字段详情和脱敏 JSON。

标签使用语义化 tab 模式，支持键盘左右键切换，并在手机上保持可见且不横向溢出。

## 5. 概览设计

### 5.1 安全状态带

概览顶部使用一条全宽状态带，而不是五张并列卡片。它展示：

- 时间状态：在窗口内、已过期、尚未生效或缺少声明。
- 到期时间与剩余时间。
- 算法。
- 固定状态“签名未验证”。
- 高风险权限计数。

状态带同时使用图标、文字和边框，不只依赖颜色。签名未验证始终保持可见。

### 5.2 账号仪表盘

账号信息使用连续的两栏定义列表，不使用卡片套卡片：

- JWT 声明的套餐。
- 账号/工作区类型。
- 认证方式。
- 邮箱是否验证。
- 计算驻留策略。
- 签发者与受众。

敏感值显示固定长度遮罩和眼睛图标按钮。短字符串、布尔值和时间使用普通文本；数组、对象及长内容才使用代码容器。

### 5.3 关键提示

概览最多显示三条高价值提示：未验签、高风险写权限、过期/尚未生效。普通未知字段不作为黄色风险警告，而是在高级检查器中标记为“未解释字段”，避免把“未知”误解为“危险”。

## 6. 命名空间与 claim 解释

### 6.1 命名空间归并

解释器识别以下常见命名空间：

- `https://api.openai.com/auth` → `OpenAI Auth`
- `https://api.openai.com/profile` → `OpenAI Profile`

界面只显示短 key，例如 `chatgpt_account_user_id`。完整路径保留在字段详情和脱敏 JSON 中。未知命名空间使用主机名或最后一级路径生成可读分组，但不丢失原路径。

### 6.2 claim 描述表

常见 claim 使用稳定描述表，至少包含：中文名称、简短说明、所属分区、敏感性、格式化方式和可选风险级别。`chatgpt_plan_type` 等字段同时出现在 OpenAI Auth 命名空间和顶层时，优先使用命名空间中的值；缺失时再回退到顶层值。所有套餐信息都标记为 JWT 声明，不推断当前订阅状态。首批覆盖：

- `alg`、`typ`、`kid`
- `iss`、`aud`、`client_id`
- `iat`、`nbf`、`exp`、`pwd_auth_time`
- `amr`、`email_verified`、`is_signup`、`sl`
- `chatgpt_plan_type`、`chatgpt_compute_residency`
- `scp`
- 常见 user/account/org/workspace/session 标识符

描述表不是固定 schema。无法识别的 claim 仍完整保留，并显示原始 key。

### 6.3 时间格式

`iat`、`nbf`、`exp` 按 JWT NumericDate 秒解释。已知的 `pwd_auth_time` 允许秒或毫秒输入，通过量级判断后显示北京时间，并标记为“认证时间声明”。所有时间同时保留原值。

## 7. 权限视图

`scp` 数组被解释为权限项目，不再只显示代码数组。每项包含原始 scope、中文含义和风险级别：

- `model.request` → 模型调用，中风险。
- `model.read` → 模型读取，低风险。
- `organization.read` → 组织读取，中风险。
- `organization.write` → 组织写入，高风险。
- `openid`、`email`、`profile` → 身份信息，低风险。
- `offline_access` → 离线访问，中风险。

未知 scope 显示“未解释”，不自动判定为高风险。用户可通过分段控件筛选“全部 / 高风险 / 写入 / 身份”。

风险级别是本工具基于 scope 名称提供的本地阅读提示，不代表 OpenAI 的官方权限评级，也不证明服务器会授予该权限。

## 8. 高级检查器

桌面采用双栏布局：

- 左栏：搜索框、分类列表、结果计数和字段列表。
- 右栏：选中字段的中文名称、原始 key、完整路径、格式化值、原始值类型和敏感状态。

手机端左栏变为菜单或选择器，字段详情占满宽度。

搜索匹配中文名称、短 key、完整路径和值；敏感值在未显示时不得参与可见搜索结果摘要。字段列表使用稳定高度，长路径不再直接占据主列表。

脱敏 JSON 位于检查器底部的折叠区域。复制按钮始终序列化脱敏副本，不受当前字段是否临时显示影响。

## 9. 敏感字段交互

- 默认显示固定长度遮罩，不泄露原值长度。
- 使用眼睛图标按钮，tooltip 和 `aria-label` 写明字段名称。
- 点击后显示 10 秒，并在按钮旁显示倒计时。
- 可立即隐藏；清空、重新解析、切换字段或按 `Esc` 会立即隐藏。
- 自动隐藏时通过 `aria-live="polite"` 宣布状态。
- 复制、搜索索引和页面日志均不使用未脱敏副本。

## 10. 错误与空状态

错误继续使用中文可操作文案。发生错误时：

- 输入框设置 `aria-invalid="true"`。
- 通过 `aria-describedby` 关联错误信息。
- 焦点返回输入框，并保留输入以便修正。
- 用户再次输入时清除错误状态。
- 旧结果在新解析开始前清除，避免把错误输入与旧结果混淆。

没有权限、没有时间声明或没有可解释 claim 时使用安静的空状态，不使用警告色。

## 11. 视觉系统

### 11.1 色彩

基础色使用冷白、石墨黑和中性灰；深绿只用于主要操作与安全完成状态。琥珀用于警告，红色用于错误/过期，蓝色用于信息提示。界面不能由单一绿色家族主导。

浅色与深色均满足正文和重要状态的 WCAG AA 对比度。颜色之外始终提供图标或文字。

### 11.2 形状与层级

- 组件圆角 6–8px。
- 只在输入工作区、检查器和必要的重复项目使用边框容器。
- 页面分区使用留白、分隔线和背景带，不把所有内容做成浮动卡片。
- 阴影非常克制，只用于浮层或焦点状态。
- 不使用渐变、装饰性光斑、插画或无意义动画。

### 11.3 字体与密度

使用系统无衬线字体；原始 key、路径和 JSON 使用系统等宽字体。应用标题 18–20px，区块标题 16–18px，正文 14–15px，辅助文字不低于 12px。字距保持 0。

固定尺寸的工具栏、标签、图标按钮和状态项使用稳定高度，动态内容不得导致布局跳动。

## 12. 技术架构

源码采用模块化 Vanilla JavaScript、HTML 和 CSS，避免为单页工具引入 React 状态层。构建使用 Vite，将模块、样式和 Lucide 图标打包进一个 HTML 产物。运行时不加载外部脚本、字体、图片或样式。

建议目录：

```text
src/
  index.html
  styles.css
  main.js
  core/
    jwt.js
    time.js
    redaction.js
    claims.js
    permissions.js
  ui/
    app.js
    overview.js
    permissions.js
    inspector.js
    reveal.js
scripts/
  build-singlefile.mjs
tests/
dist/index.html
index.html
```

构建先在临时 `dist/index.html` 完成核对，再把相同内容写入仓库根目录的 `index.html`。交给用户的发布包只包含根目录 `index.html`；`dist/` 不进入发布包和版本控制。纯函数从源码模块直接测试，不再从生成 HTML 中抽取脚本。

内容安全策略继续阻止连接、外部资源、表单提交和持久化存储。构建后执行静态扫描，确认产物不包含外部 URL 加载、网络 API、真实 token 或 source map 内嵌源码泄漏。

## 13. 测试策略

测试只使用合成 JWT，覆盖：

- 原有解析、时间、脱敏、复制和清空行为。
- 命名空间归并和短 key。
- claim 中文解释与未知 claim fallback。
- scope 分类、风险等级和筛选。
- `pwd_auth_time` 秒/毫秒转换。
- 搜索不泄露敏感值。
- 倒计时、自动隐藏和 live region 状态。
- 错误时的 `aria-invalid`、`aria-describedby` 和焦点返回。
- 标签键盘切换、手机单栏和无横向溢出。
- 构建产物单文件、无网络、无持久化和无真实凭据。

浏览器验收使用桌面 1440×1000、手机 390×844、浅色和深色模式；检查首屏、概览、权限、高级检查器、错误状态、复制和 10 秒自动隐藏。

## 14. 非目标

V2 不包含：

- 在线 token 可用性或额度查询。
- JWT 签名验证、公钥下载或 token 编辑。
- 多 token、历史记录、导入导出或账号切换。
- 登录、刷新、转换、代理或任何第三方请求。
- 云端同步、遥测或分享链接。

## 15. 验收标准

1. 最终发布包只有一个 `index.html`，可通过 `file://` 双击运行。
2. 解析真实形态的合成 token 后，首屏能看到安全状态、套餐、认证和关键权限。
3. OpenAI 命名空间不再在主视图重复显示完整 URL。
4. 权限有中文解释和风险等级，写权限清晰可见。
5. 高级检查器支持搜索、分类和字段详情。
6. 敏感值默认遮罩，显示 10 秒后自动隐藏并可访问地通知。
7. 错误状态与输入正确关联并返回焦点。
8. 页面无外部请求、无持久化、无真实 token，复制始终脱敏。
9. 桌面、手机、浅色、深色和键盘流程均通过浏览器验收。
10. 视觉结果符合“克制、专业、优雅”的个人安全工具定位。
