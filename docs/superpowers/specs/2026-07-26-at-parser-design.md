# AT 本地解析器设计

## 1. 项目目标

构建一个供个人在本机使用的单 AT 解析网页。用户把 ChatGPT access token 粘贴到页面后，工具在浏览器内完成 JWT Header 和 Payload 解码，并以中文分类摘要和脱敏 JSON 展示结果。

首版强调三个目标：

1. 双击 `index.html` 即可使用，不要求安装 Node.js 或其他依赖。
2. 输入和解析结果不离开当前浏览器页面，不产生网络请求，也不保存历史记录。
3. 清楚区分“解码”和“验证”：工具只读取 JWT 声明，不验证签名、撤销状态或服务端可用性。

## 2. 使用者与使用场景

首版只面向项目所有者本人，在个人电脑上一次解析一个 AT。典型流程是：

1. 打开本地 `index.html`。
2. 粘贴一个 AT，或粘贴带有 `Bearer ` 前缀的值。
3. 点击“解析”。
4. 查看算法、账号、时间、权限和安全提示等分类结果。
5. 必要时短暂显示某个敏感字段，或复制脱敏后的 JSON。
6. 点击“清空全部”、按 `Esc` 或刷新页面，移除当前结果。

## 3. 首版范围

### 3.1 包含的能力

- 一次解析一个三段式 JWT。
- 兼容可选的 `Bearer ` 前缀及输入首尾空白。
- Base64URL 解码 Header 和 Payload，并按 UTF-8 解析 JSON。
- 展示分类摘要和格式化、脱敏后的原始 JSON。
- 将 `iat`、`nbf`、`exp` 转换为北京时间。
- 根据本机当前时间标记声明时间状态。
- 识别常见身份、账号、权限、套餐和认证方式字段。
- 保留并展示无法识别的字段，不依赖固定的 OpenAI Token Schema。
- 默认遮盖敏感字段，允许逐项显示 10 秒。
- 复制脱敏 JSON。
- 一键清空全部数据。

### 3.2 明确不包含的能力

- JWT 签名验证或公钥下载。
- 调用 OpenAI 或 ChatGPT 接口检测 token 是否可用。
- token 获取、刷新、转换、交换或代理。
- 多 token、批量导入或历史记录。
- token 文件导入、导出或完整 token 复制。
- Cookie、`localStorage`、`sessionStorage`、IndexedDB 或服务工作线程。
- 账号登录、团队共享、云端同步、统计分析或遥测。

## 4. 技术架构

应用由单个 `index.html` 构成，样式和脚本均内嵌。页面不加载外部字体、图片、脚本、样式或分析服务。

虽然代码位于同一个文件中，JavaScript 仍按职责划分为三个逻辑单元：

### 4.1 JWT 解码器

负责规范化输入、检查 JWT 三段结构、解码 Base64URL、按 UTF-8 读取内容及解析 JSON。它只返回结构化数据或明确错误，不处理界面。

### 4.2 字段解释与脱敏器

负责递归遍历对象、分类字段、转换 NumericDate 时间、计算声明时间状态以及生成脱敏副本。原始解码对象与脱敏副本分离，复制操作永远使用脱敏副本。

### 4.3 界面控制器

负责输入、状态切换、结果渲染、敏感字段临时显示、复制、计时器和数据清除。解析成功后立即清空输入框及原始 token 引用；为了支持逐项显示，解码后的字段值会留在页面内存中，直到用户清空或刷新。

JavaScript 无法保证浏览器引擎立即擦除已释放字符串的物理内存，因此页面只承诺清除可访问引用和界面内容，不宣称安全内存擦除。

## 5. 网络与存储约束

页面不调用 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`sendBeacon` 或表单提交。HTML 使用内容安全策略阻止连接和外部资源，策略至少包含：

- `default-src 'none'`
- `script-src 'unsafe-inline'`
- `style-src 'unsafe-inline'`
- `connect-src 'none'`
- `img-src data:`
- `font-src 'none'`
- `frame-src 'none'`
- `form-action 'none'`
- `base-uri 'none'`

应用不读写浏览器持久化存储。刷新页面后不存在恢复解析结果的机制。

## 6. 页面结构与视觉设计

页面采用简洁的安全工具风格，自动跟随系统深色或浅色模式，并由以下区域组成：

1. **页面标题与安全说明**：明确写出“所有解析均在本地完成”和“已解码但未验签”。
2. **输入卡片**：大尺寸 AT 输入框，以及“解析”和“清空”按钮。
3. **状态摘要**：展示格式、算法、签发时间、到期时间和时间状态。
4. **分类结果卡片**：账号与身份、认证信息、权限、时间、安全信息和其他字段。
5. **脱敏 JSON**：默认折叠，展开后显示格式化 JSON。
6. **底部安全提示**：提醒用户不要分享真实 token，泄露后应撤销相关会话。

状态不能只依赖颜色表达。有效、过期、尚未生效、警告和错误均同时显示图标与文字。页面在手机和桌面宽度下都可使用，交互元素具备可见焦点、键盘操作和适当的无障碍标签。

界面默认使用中文；JWT 键名保持原文，避免翻译导致歧义。

## 7. 数据流

1. 用户粘贴文本并点击“解析”。
2. 控制器去除首尾空白和不区分大小写的 `Bearer ` 前缀。
3. 解码器确认输入恰好有三个非空片段。
4. 解码器分别解码 Header 与 Payload；Signature 只检查是否存在，不解码为业务数据，也不验证。
5. Header 与 Payload 必须是 JSON 对象；数组、字符串或其他顶层类型视为结构异常。
6. 解释器构建分类摘要、时间状态及脱敏副本。
7. 控制器清空输入框和原始 token 引用，再渲染结果。
8. 用户可以短暂显示某个敏感值；10 秒后该字段自动恢复遮盖。
9. 复制操作序列化脱敏副本，不受当前是否显示某个字段影响。
10. 清空、按 `Esc` 或刷新会移除结果并取消全部显示计时器。

## 8. 时间处理

`iat`、`nbf`、`exp` 按 JWT NumericDate 秒数解释。界面同时显示原始数值和北京时间；无法转换的值保留原文并显示格式警告。

时间状态规则如下：

- `nbf` 存在且当前时间早于 `nbf`：尚未生效。
- `exp` 存在且当前时间大于或等于 `exp`：已过期。
- 不满足以上条件且至少存在 `nbf` 或 `exp`：在声明时间窗口内。
- `nbf` 和 `exp` 均不存在：缺少时间声明。

`iat` 只用于展示签发时间，不单独决定有效性。所有状态旁均说明：时间判断不等同于签名有效或服务端接受。

## 9. 字段分类与脱敏

分类器识别常见字段，但任何未知字段仍在“其他字段”和脱敏 JSON 中展示。OpenAI 可能改变内部声明，因此实现不得把当前字段集合视为稳定公共接口。

以下键或键模式默认视为敏感：

- `email`、`name`、`sub`、`jti`、`session_id`
- 以 `_id` 或 `_ids` 结尾的键
- 包含 user、account、organization、org、workspace 或 verified identity 含义的标识符字段

界面遮盖值统一显示为固定长度的圆点，不通过长度泄露原值信息。数组和嵌套对象递归处理。复制 JSON 时，敏感值替换为字符串 `[REDACTED]`；不会把部分原值写入剪贴板。

逐项显示仅影响当前字段的视觉呈现：

- 显示持续 10 秒。
- 再次点击可以立即隐藏。
- 清空或按 `Esc` 会立即隐藏并移除全部字段。
- 复制操作仍使用脱敏副本。

## 10. 错误与警告

错误阻止结果渲染，警告允许继续查看可解析内容。

### 10.1 错误

- 输入为空。
- 去除 `Bearer ` 后内容为空。
- JWT 不是三个非空片段。
- Header 或 Payload 不是合法 Base64URL。
- 解码内容不是合法 UTF-8 或 JSON。
- Header 或 Payload 顶层不是 JSON 对象。

### 10.2 警告

- `alg` 缺失、为 `none` 或不是常见签名算法。
- Signature 片段存在但未验证。
- `iat`、`nbf` 或 `exp` 类型不正确。
- token 已过期、尚未生效或缺少时间声明。
- 未识别的字段或结构。

错误信息使用中文说明用户可以采取的操作，不显示堆栈信息。解析新输入前会移除旧错误和旧结果，避免误读。

## 11. 复制兼容性

优先使用 Clipboard API 写入脱敏 JSON。如果本地 `file://` 环境不允许 Clipboard API，则使用页面内临时文本区域进行兼容复制；如果浏览器仍阻止自动复制，则选中脱敏文本并提示用户手动复制。任何路径都不能复制完整 token 或未脱敏对象。

## 12. 测试策略

测试只使用程序生成的虚构 JWT。测试数据可以带有虚构 Header、Payload 和虚构 Signature 内容，但不得包含真实 token、邮箱、账号或会话信息。

需要覆盖：

- 标准三段式 JWT。
- 带 `Bearer ` 前缀及额外空白的输入。
- Header 或 Payload 中的中文及其他 Unicode 内容。
- 缺少 `exp`、已经过期和 `nbf` 尚未生效。
- 空输入、片段数错误和空片段。
- 非法 Base64URL、非法 UTF-8 和非法 JSON。
- Header 或 Payload 顶层不是对象。
- `alg=none`、缺少 `alg` 和未知算法。
- 多层对象及数组中的敏感字段。
- 逐项显示后 10 秒自动隐藏。
- 复制结果始终脱敏。
- 点击清空、按 `Esc` 和刷新后的状态清除。
- 键盘导航、焦点可见性和手机宽度布局。

安全检查包括确认源码不含网络调用或持久化存储调用，并在浏览器开发工具中确认页面加载和解析过程没有网络请求。

## 13. 验收标准

首版完成需同时满足：

1. 用户可以直接双击 `index.html` 打开工具。
2. 正常输入可以即时得到分类摘要和脱敏 JSON。
3. 页面没有外部依赖，加载和解析均不产生网络请求。
4. 页面不读写 Cookie 或浏览器持久化存储。
5. 解析成功后输入框与原始 token 引用被清除。
6. 敏感字段默认遮盖，逐项显示会在 10 秒后自动恢复。
7. 复制结果不包含未脱敏值。
8. 错误和警告均有清楚、可操作的中文提示。
9. 页面始终明确说明未验证签名和服务端可用性。
10. 桌面、手机和纯键盘操作均可完成核心流程。
11. 项目源码和测试数据不包含任何真实 token 或个人信息。

## 14. 后续版本候选

以下能力不进入首版，只有在实际需要出现后再单独设计：

- 批量解析。
- 可配置的脱敏规则。
- 独立测试页面或构建工具。
- 离线公钥导入与签名验证。
- 多语言界面。
- 将单文件应用拆分为模块化前端工程。
